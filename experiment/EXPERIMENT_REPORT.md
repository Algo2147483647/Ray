# Systematic Report for the Ray Experiment Suite

## 1. Scope and purpose

This report reconstructs the experiments under `experiment/` from their current
source code, scene files, launch scripts, generated metadata, and stored artifacts.
It documents what each experiment is intended to test, how it is constructed, what
can presently be reproduced, what has actually been demonstrated, and where the
evidence is incomplete.

The report covers engine-facing experiments only. Studio is treated as the scene
composition and launch layer; claims about geometry, materials, spectra, cameras,
films, or transport refer to behavior implemented by the Ray engine.

The suite contains five experiment groups:

1. a 42-cell geometry coverage matrix;
2. a collection of four-dimensional projection and volume-film scenes;
3. hyperbolic honeycomb and invariant-driven showcase generators;
4. a 42-sphere material comparison matrix;
5. a dispersive and absorbing triangular-prism experiment.

## 2. How to interpret the evidence

The repository contains different forms of evidence. To avoid overstating results,
this report uses the following levels.

| Level | Meaning | Experiments currently reaching it |
|---|---|---|
| A: automated rendered-result verification | A program evaluates raw rendered data against explicit numerical acceptance criteria. | Triangular-prism dispersion |
| B: generated-construction invariants | The generator checks mathematical invariants before emitting the scene and records the values in the output JSON. | Hyperbolic showcase |
| C: stored visual result | A representative image exists and can be inspected, but no automated image or error metric defines pass/fail. | Geometry matrix, material matrix, hyperbolic images, 4D exports |
| D: configuration/prototype | A scene definition exists, but a uniquely matched result and reproducible export chain are not stored. | Several 4D Klein-bottle variants |

A visually convincing image is useful evidence of integration and coverage, but it
is not a substitute for a numerical test of geometry, convergence, energy, or
performance.

## 3. Suite-level experimental design

### 3.1 Shared principles

The experiments use three recurring design patterns.

**Controlled comparison.** The geometry and material matrices hold most scene
variables fixed while changing one class of input. Geometry samples share a room,
camera, and material library. Material samples share sphere geometry and room
lighting.

**Construction from mathematical invariants.** The hyperbolic generators derive
reflections, distances, cell orbits, and geodesic measurements rather than placing
all objects manually.

**Diagnostic/presentation separation.** The prism scene separates common apparatus,
the prism medium, diagnostic rendering, verification overrides, and beauty-render
settings into composable files. This permits a low-resolution numerical test and a
high-resolution presentation render without changing the physical core of the
scene.

### 3.2 Common threats to validity

- Monte Carlo renders are stochastic, and the experiment files do not record a
  common random seed.
- Most artifacts lack a manifest containing the engine commit, complete command,
  hardware, elapsed time, memory use, and output checksum.
- Some stored image dimensions differ from the current scene defaults, indicating a
  historical command-line override or a configuration change after rendering.
- Tone mapping and exposure can hide or exaggerate differences. Diagnostic claims
  should be derived from linear raw films whenever possible.
- A single camera and lighting arrangement cannot expose every geometric or material
  failure mode.
- The words `benchmark matrix` currently mean feature coverage and comparison, not a
  benchmark of execution time, memory, convergence rate, or numerical error.

### 4.3 Mathematical families represented

The matrix intentionally crosses several representations:

- explicit analytic primitives such as spheres, cones, cylinders, tori, ellipsoids,
  and paraboloids;
- polynomial implicit surfaces represented by a zero set

  $$
  S = \{\mathbf{x} \in \mathbb{R}^3 \mid f(\mathbf{x}) = 0\};
  $$

- norm balls defined by

  $$
  \|\mathbf{x}\|_p =
  \left(|x|^p + |y|^p + |z|^p\right)^{1/p};
  $$

- parametric curves and surfaces, where a map

  $$
  \mathbf{p}(u,v) : \Omega \subset \mathbb{R}^2 \rightarrow \mathbb{R}^3
  $$

  supplies the surface;
- polyhedra and star polyhedra assembled from finite vertices and faces;
- blended fields such as metaballs, whose surface is an isovalue of a sum of local
  influence functions.

This variety makes the image useful as an integration test across parsers,
intersection algorithms, normal computation, bounding structures, and shading.

### 4.4 Procedure

```powershell
Set-Location experiment/geometric_object/geometry-benchmark-matrix
cmd /c run.cmd
```

`run.cmd` composes, in order, `room.json`, `main.json`, `materials.json`, and
`geo-r01.json` through `geo-r06.json`. `run_endless.cmd` adds unbounded accumulation,
a checkpoint every 50 units of the engine's checkpoint interval, and timestamped
temporary/intermediate paths.

### 4.5 Result and interpretation

The stored matrix visibly contains six rows of seven cells and demonstrates that a
large heterogeneous scene reached an image. The shapes include smooth primitives,
singular algebraic surfaces, open surfaces, thin curves, concave polyhedra, and
transparent objects. This is strong integration evidence but remains qualitative:
there is no silhouette reference, intersection-count oracle, normal-error metric,
or per-cell pass/fail result.

### 4.6 Gaps and recommended measurements

- Add a per-cell object identifier to a machine-readable manifest.
- Render a normal, depth, and object-ID diagnostic pass for each cell.
- Define a toleranced image comparison against a reviewed baseline.
- Add isolated low-resolution scenes so one failed object does not obscure the
  remaining 41.
- Record render time, rays per second, peak memory, and acceleration-structure build
  time if this is to become a performance benchmark.
- The local README refers to a backup file named
  `geo-r05-c07-diagonal-ridged-torus-backup.json`; that file is not present in the
  current experiment directory and should not be treated as a reproducible input.

## 5. Four-dimensional experiments

### 5.1 Question and representation

These scenes test whether the engine can render geometry in four-dimensional scene
space while storing a three-dimensional film. A rank-3 film samples a field

$$
L(i,j,k), \qquad
0 \le i < N_x,\quad 0 \le j < N_y,\quad 0 \le k < N_z,
$$

rather than the ordinary rank-2 image $L(i,j)$. The resulting data must be sliced,
projected, or volume-rendered for human inspection.

The repository's [`film-volume-viewer`](../tools/film-volume-viewer/README.md) is the
appropriate inspection tool for rank-2 and rank-3 film files.

### 5.2 Hypercube geometry-focus scene

`4d-hypercube-geometry-focus.json` contains:

- a Lambertian 4D cuboid spanning $[-0.825,0.825]^4$;
- an emissive hypersphere centered at
  $(-1.6,1.9,1.15,-1.35)$ with radius $0.7$;
- a 4D orthographic N-dimensional camera;
- a $100 \times 100 \times 100$ RGB film;
- 160 samples, eight threads, Reinhard tone mapping, exposure 1.8, and gamma 2.2.

The cuboid is the Cartesian set

$$
C = \{\mathbf{x}\in\mathbb{R}^4 : -0.825 \le x_d \le 0.825,
\ d=1,2,3,4\},
$$

while the hypersphere boundary satisfies

$$
\|\mathbf{x}-\mathbf{c}\|_2^2 = r^2.
$$

The experiment studies how four-dimensional occlusion and illumination appear when
sampled into a 3D film volume.

### 5.3 Direct normal-palette diagnostic

`4d-hypercube-geometry-focus-direct.json` uses the same basic cuboid and film shape
but switches to a direct diagnostic presentation:

- 64 samples;
- `normal_palette` emission for signed dominant-normal identification;
- linear tone mapping with gamma 1.

Its purpose is structural labeling rather than photorealistic shading. Comparing it
with the geometry-focus scene helps separate topology or cell orientation from
lighting effects.

### 5.4 Klein-bottle tube scenes

The three Klein scenes encode a tubular neighborhood of a 4D Klein-bottle
parameterization. Conceptually, a parameterized center surface

$$
\mathbf{k}(u,v) \in \mathbb{R}^4
$$

is thickened by accepting points within an epsilon distance:

$$
S_\varepsilon = \{\mathbf{x}\in\mathbb{R}^4 :
\inf_{u,v}\|\mathbf{x}-\mathbf{k}(u,v)\|_2 \le \varepsilon\}.
$$

| Scene | Geometry parameters | Film/camera intent | Samples |
|---|---|---|---|
| `klein.json` | $R=1.5$, $r=0.5$, thickness $0.06$ | General 4D orthographic volume, $100^3$ | 16 |
| `klein-nonselfintersection.json` | $R=1.35$, $r=0.62$, thickness $0.075$ | Camera and slice extents chosen to show that an apparent 3D crossing separates along the fourth coordinate | 200 |
| `klein-showcase.json` | $R=1.35$, $r=0.62$, thickness $0.075$ | Wide showcase framing, film $96\times36\times36$ | 128 |

UV-based emission stripes make parameter-space orientation visible. The
non-self-intersection variant is especially important: a projected crossing in three
coordinates does not imply an intersection in $\mathbb{R}^4$ when the fourth
coordinates differ.

## 6. Hyperbolic experiments

### 6.1 Model

Both experiments use the Klein ball model of hyperbolic three-space. Points satisfy

$$
\mathbf{x}\in B^3 = \{\mathbf{x}\in\mathbb{R}^3 : \|\mathbf{x}\|<1\}.
$$

Geodesics appear as Euclidean chords, which makes line-like geometry convenient,
while metric quantities remain non-Euclidean.

### 6.2 Regular cubic honeycomb generator

`hyperbolic honeycomb.py` constructs a finite breadth-first subset of the regular
$\{4,3,5\}$ honeycomb. Its cells are cubes, three faces meet at each vertex, and five
cubes meet around every edge. The target dihedral angle is therefore

$$
\theta = \frac{2\pi}{5} = 72^\circ.
$$

The construction uses

$$
a^2=\sqrt{5}-2,
\qquad
a=\sqrt{\sqrt{5}-2}\approx0.485868,
$$

for the relevant Klein-coordinate cube scale.

A reflection across a Klein hyperplane represented by Euclidean unit normal
$\mathbf{n}$ and offset $c$ is implemented through

$$
k = \frac{2(\mathbf{n}\cdot\mathbf{x}-c)}{1-c^2},
$$

$$
\mathbf{x}' =
\frac{\mathbf{x}-k\mathbf{n}}{1-kc}.
$$

The generator starts from a seed cube and performs breadth-first reflection across
faces. Cell count and maximum layer bound the otherwise infinite honeycomb.

The checked-in `hyperbolic.json` currently describes a 400 x 400 RGB render with 320
samples, 317 objects, and 13 materials. The object set contains 192 finite cylinders
and 125 spheres, encoding cell edges and vertices. This checked-in scene does not
equal every generator default; pass all important arguments explicitly when
reproducing it.

Example:

```powershell
python "experiment/geometric_spaces/non-euclidean/hyperbolic honeycomb.py" --cells 25 --max-layer 3 --out experiment/geometric_spaces/non-euclidean/hyperbolic.json
npm run studio -- --script experiment/geometric_spaces/non-euclidean/hyperbolic.json
```

### 6.3 Hyperbolic showcase generator

`hyperbolic_showcase.py` focuses on interpretable invariants rather than cell count.
It constructs:

- five cells around a common edge;
- a ladder with equal hyperbolic step length;
- a geodesic triangle whose angle sum exposes negative curvature;
- colored edge and vertex elements for visual tracing.

The Klein-model distance used by the generator is

$$
d_H(\mathbf{x},\mathbf{y})=
\operatorname{arcosh}
\left(
\frac{1-\mathbf{x}\cdot\mathbf{y}}
{\sqrt{(1-\|\mathbf{x}\|^2)(1-\|\mathbf{y}\|^2)}}
\right).
$$

At a point $\mathbf{p}$, tangent vectors are compared with the Klein metric

$$
g_{\mathbf{p}}(\mathbf{u},\mathbf{v})=
\frac{\mathbf{u}\cdot\mathbf{v}}{1-\|\mathbf{p}\|^2}
+
\frac{(\mathbf{p}\cdot\mathbf{u})(\mathbf{p}\cdot\mathbf{v})}
{(1-\|\mathbf{p}\|^2)^2}.
$$

Triangle angles are obtained from the metric cosine relation

$$
\cos\alpha =
\frac{g_{\mathbf{p}}(\mathbf{u},\mathbf{v})}
{\sqrt{g_{\mathbf{p}}(\mathbf{u},\mathbf{u})
g_{\mathbf{p}}(\mathbf{v},\mathbf{v})}}.
$$

For a hyperbolic triangle,

$$
\alpha+\beta+\gamma < \pi,
\qquad
\delta = \pi-(\alpha+\beta+\gamma)>0,
$$

where $\delta$ is the angle defect.

### 7.3 Material mathematics represented

The matrix spans several BSDF and medium behaviors.

An ideal Lambertian material uses a constant diffuse BRDF

$$
f_r(\omega_i,\omega_o)=\frac{\rho}{\pi},
$$

where $\rho$ is reflectance.

Specular reflection obeys

$$
\omega_r = \omega_i - 2(\omega_i\cdot\mathbf{n})\mathbf{n}.
$$

Dielectric refraction follows Snell's law,

$$
\eta_i\sin\theta_i=\eta_t\sin\theta_t,
$$

with Fresnel reflection controlling the split between reflection and transmission.
Rough conductors and rough dielectrics replace delta-direction behavior with a
microfacet distribution whose roughness broadens highlights or transmission lobes.

Participating absorption follows Beer-Lambert attenuation,

$$
T(\lambda,d)=\exp[-\sigma_a(\lambda)d].
$$

The matrix is rendered in sampled-spectrum mode, which is important for dispersive,
colored-transmission, and wavelength-dependent materials.

### 7.4 Result and interpretation

The stored image dimensions exactly match the current 1050 x 600 configuration. It
shows materially distinct reflection sharpness, metallic tint, diffuse response,
transmission, colored attenuation, and emission under a common room setup. Repeated
entries vary with position as expected from different incident lighting and viewing
directions.

No numerical reference is attached. Consequently, the image demonstrates supported
appearance classes and comparative integration, but not energy conservation,
reciprocity, exact Fresnel values, roughness calibration, or convergence.

- Add a label/ID pass and a manifest mapping all 42 positions to material IDs.
- Add furnace tests for energy conservation.

  $$

- Add fixed-angle goniometric renders for roughness distributions.
- Record spectral transmittance through fixed path lengths for absorbing media.
- Add per-sample region statistics and a toleranced visual baseline.

## 8. Triangular-prism dispersion

### 8.1 Hypotheses

The prism experiment tests two ordered effects:

1. a Cauchy dielectric should produce wavelength-dependent refraction and spatially
   separate blue, green, and red bands on the screen;
2. adding the configured wavelength-dependent absorption should attenuate blue more
   strongly than green, and green more strongly than red.

### 8.2 Scene decomposition

| File | Responsibility |
|---|---|
| `scene.json` | Darkroom apparatus, white slit source, baffles, screen, and common materials |
| `prism-control.json` | Lossless Cauchy prism medium and eight triangular prism faces |
| `prism-absorbing.json` | Same prism with wavelength-dependent absorption |
| `diagnostic.json` | 120 x 80, 512-sample spectral diagnostic camera and core render settings |
| `verify-control.json` | Light-tracing control-film output override |
| `verify-absorbing.json` | Light-tracing absorbing-film output override |
| `beauty.json` | 1000 x 1000 presentation camera, warm practical light, tone mapping, and explicit BDPT render |
| `verify.cmd` | Renders both diagnostic variants and invokes the spectral-film probe |
| `run.cmd` | Renders the absorbing presentation variant |

The common scene has 34 objects and ten materials. The narrow white slit is modeled
with two emissive, area-sampleable triangles. Black baffles suppress paths that do
not pass through the intended apparatus, and a white screen receives the dispersed
light.

### 8.3 Dispersion model

The prism uses a three-term Cauchy model with coefficients

$$
A=1.35,\qquad B=0.025,\qquad C=0,
$$

The engine receives wavelengths in nanometers and evaluates the Cauchy polynomial in
micrometers:

$$
\lambda_{\mathrm{um}}=\frac{\lambda_{\mathrm{nm}}}{1000}.
$$

The refractive index is

$$
n(\lambda)=A+\frac{B}{\lambda_{\mathrm{um}}^2}
+\frac{C}{\lambda_{\mathrm{um}}^4}.
$$

This gives approximately $n(400\,\mathrm{nm})=1.50625$,
$n(500\,\mathrm{nm})=1.45$, $n(600\,\mathrm{nm})=1.41944$, and
$n(700\,\mathrm{nm})=1.40102$. Shorter visible wavelengths therefore receive the
larger refractive index and a different refraction angle under Snell's law.

For a thin-prism intuition only, the angular deviation scales approximately as

$$
\delta(\lambda)\approx[n(\lambda)-1]\,\alpha,
$$

where $\alpha$ is the prism apex angle. The renderer uses the actual prism boundary
interactions, not this approximation.

### 8.4 Absorption model

The absorbing variant samples $\sigma_a(\lambda)$ at four visible wavelengths:

| Wavelength | $\sigma_a$ |
|---:|---:|
| 400 nm | 3.2 |
| 500 nm | 1.4 |
| 600 nm | 0.45 |
| 700 nm | 0.10 |

For path length $d$ through the medium, Beer-Lambert attenuation is

$$
L_{\mathrm{out}}(\lambda)=
L_{\mathrm{in}}(\lambda)\exp[-\sigma_a(\lambda)d].
$$

The coefficient ordering predicts stronger attenuation at short wavelengths.

### 8.5 Diagnostic measurement

The spectral probe integrates three bands:

| Band | Interval |
|---|---|
| Blue | 420-480 nm |
| Green | 500-580 nm |
| Red | 600-680 nm |

For band $b$, a screen-axis centroid is conceptually

$$
\bar{x}_b =
\frac{\sum_{x,y} x\,E_b(x,y)}
{\sum_{x,y} E_b(x,y)},
$$

where $E_b$ is the band-integrated energy over the complete diagnostic film.
The dispersion span is

$$
S=\max_b\bar{x}_b-\min_b\bar{x}_b.
$$

For the 120-pixel-wide diagnostic film, the coded criteria require:

- monotonic blue/green/red centroid ordering in the expected screen direction;
- $S \ge \max(2\ \text{pixels},0.04W)=4.8$ pixels;
- when comparing absorbing and control films, centroid disagreement no greater than
  $\max(1.5\ \text{pixels},0.02W)=2.4$ pixels;
- finite positive band-energy ratios;
- $q_B<q_G<q_R$, with $q_B\le0.9$ and $q_R\le1.15$.

Here

$$
q_b=\frac{E_{b,\mathrm{absorbing}}}{E_{b,\mathrm{control}}}.
$$

## 10. Reproducibility findings

### 10.1 What is already strong

- Scene inputs are text and live beside their experiment.
- The matrix experiments control important scene variables.
- Hyperbolic scenes can be regenerated from mathematical code.
- The hyperbolic showcase records validation outputs in JSON.
- The prism separates physical apparatus, variants, diagnostic settings, and beauty
  settings cleanly.
- The prism retains raw spectral films outside the experiment directory and provides
  a command-line verifier with explicit thresholds.

## 11. Recommended experimental roadmap

### Priority 1: make results traceable

1. Add `results/manifest.json` to every experiment.
2. Capture commit, command, input hashes, film metadata, seed, host, timing, and output
   hashes automatically.
3. Store raw films whenever a numerical claim depends on them.
4. Move historical images with unknown provenance into a clearly labeled `legacy/`
   area once reviewed.

### Priority 2: turn visual galleries into tests

1. Add deterministic object-ID, normal, and depth passes to the geometry matrix.
2. Add region labels and numerical reflectance/transmittance probes to the material
   matrix.
3. Use toleranced perceptual or statistical comparison for noisy beauty renders.
4. Keep small isolated regression scenes beside the large matrices.

### Priority 3: complete the mathematical experiments

1. Store honeycomb validation metadata just as the showcase already does.
2. Measure face-plane residuals, reflected-cell uniqueness, and graph adjacency for
   generated honeycombs.
3. Script 4D volume-film slicing and camera-axis labeling.
4. Add 4D analytic fixtures with known intersections and distances, so success does
   not depend only on a human-readable projection.

### Priority 4: add performance methodology

If the matrices are intended to be benchmarks in the conventional sense, record:

- warm-up policy and number of repetitions;
- median and dispersion of elapsed time;
- rays or samples per second;
- acceleration-structure build time;
- peak resident memory and output size;
- CPU/GPU identity, thread count, Go version, and power/performance mode;
- a fixed resolution, sample budget, seed policy, and compiler configuration.

Report medians and a spread statistic rather than a single run. For example, with
times $t_1,\ldots,t_n$, report

$$
\tilde{t}=\operatorname{median}(t_i)
$$

and the median absolute deviation

$$
\operatorname{MAD}=\operatorname{median}(|t_i-\tilde{t}|).
$$

## 12. Final assessment

The experiment directory already demonstrates unusually broad engine coverage:
analytic, implicit, parametric, polyhedral, non-Euclidean, four-dimensional,
spectral, dielectric, participating-medium, and bidirectional/light-tracing paths all
appear in concrete scenes.

Its strongest scientific patterns are the hyperbolic showcase's invariant-driven
generator and the prism experiment's separation of control, treatment, diagnostic,
presentation, and automated verification. Those patterns should become the default
for the rest of the suite.

The principal weakness is provenance, not a lack of experiments. Several attractive
stored images cannot yet be tied unambiguously to the current configuration and an
exact command, and the visual matrices have no numerical oracle. Adding manifests,
raw diagnostic films, explicit seeds, scripted 4D exports, and toleranced automated
checks would turn the current gallery of successful demonstrations into a durable
experimental and regression framework.
